# Protocole de Sécurité et Intégrité (v6.3.4-STABLE)

Ce document définit les règles de fer garantissant que l'ESP32 reste **toujours accessible à distance** et protège l'intégrité du SPA.

## 1. Priorité Absolue : Le WiFi et l'OTA
- **Règle d'or** : Aucune boucle d'attente (`delay()`, `read_bytes()`) ne doit dépasser **2 millisecondes** dans le code UART.
- **Priorité Système** : En cas de conflit, le code abandonne le traitement UART pour prioriser la pile TCP/IP (OTA Protection).

## 2. Sniper Engine & Buffers (Fix 5-Octets)
Utilisation du **Sniper Engine v2** avec buffer circulaire isolé. Les trames de 5 octets (`1B`) sont traitées de manière atomique pour éviter toute corruption de mémoire.

## 3. Gestion des Sockets (Fix Erreur EMFILE 23)
- **Timeout Strict 1s** : Toutes les requêtes vers Eedomus sont bridées à 1s de timeout.
- **Libération Immédiate** : Les sockets sont fermés immédiatement après réponse pour garantir la disponibilité de l'OTA et du serveur web.

## 4. Le Firewall Matériel (Verrouillage)
- **Mode Firewall** : Activé via `sw_lock`.
- **Intégrité du Bus** : Le firewall bloque les injections de commandes clavier tout en maintenant le flux des trames de statut et le heartbeat. Cela empêche toute manipulation physique non autorisée.

## 5. Limite de Sécurité Thermique
- **Hard-Cap 40°C** : Le contrôleur refuse d'injecter ou de relayer toute consigne supérieure à 40°C, même si demandée par le clavier ou l'API.
- **Rollback de Secours** : En cas d'instabilité, la version baseline stable est conservée dans l'historique de déploiement.
