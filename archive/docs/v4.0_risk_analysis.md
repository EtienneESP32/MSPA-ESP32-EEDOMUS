# Analyse de Risques : Transition Firmware v4.0

Le passage à l'architecture "Pilote" (v4.0) est une modification structurelle majeure. Cette analyse identifie les points de rupture potentiels et les mesures d'atténuation.

## 1. Matrice des Risques

| Risque | Impact | Probabilité | Description | Mitigation |
| :--- | :--- | :--- | :--- | :--- |
| **Gigue UART (Jitter)** | Critique | Moyenne | Le nouveau code retarde le transit des trames Poll (0D). Le SPA passe en erreur E1. | Priorité interrupt-driven pour le forwarding des trames système. |
| **Blocage HTTP (Eedomus)** | Majeur | Haute | Le push vers Eedomus fige l'ESP32 pendant 2s. Crash de la com UART. | Implémenter une file d'attente asynchrone (Task-based). |
| **Désynchronisation d'État** | Moyen | Basse | L'ESP32 croit que le SPA est ON mais il est OFF. Injection de trames inutiles. | Validation cyclique obligatoire via ID 0x08. |
| **Erreur de Firewall** | Majeur | Basse | Le mode Lock bloque accidentellement les trames Vitales (Poll/Temp). | Liste blanche stricte : Seules les trames Commandes (01, 02, 03, 19) sont filtrables. |
| **Stack Overflow (C++)** | Moyen | Basse | Erreur mémoire dans le composant custom provoquant un reboot cyclique. | Test de stabilité 24h en mode "Observateur Silencieux" (Release 4.0). |

## 2. Analyse Technique Détailée

### A. Le Timing UART (Le Point Critique)
Le SPA fonctionne à 9600 bps. Une trame de 4 octets prend environ 4ms à être transmise. Si l'ESP32 introduit un délai de traitement > 10-20ms sur les trames de dialogue (Poll/Response), la carte mère risque de considérer que le clavier est déconnecté.
- **Solution** : Le "Firewall" doit fonctionner en mode "Passthrough transparent" par défaut avec un temps de décision < 1ms.

### B. Fiabilité du Relais 0x08
Nous basons notre UI sur l'ID `0x08`. Si cet ID vient à manquer ou à changer de comportement (ex: mise à jour hardware silencieuse du SPA), l'interface deviendra sourde.
- **Solution** : Garder un mode "Diagnostic" qui permet de voir la valeur brute de `1A` en cas de doute.

### C. Sécurité du SPA (Protection Matérielle)
Le SPA possède ses propres sécurités (Flow switch, protection surchauffe). Notre code ne doit jamais empêcher ces sécurités de remonter vers le clavier.
- **Solution** : Les trames d'erreur et de statut (`1A`, `06`, `1B`) ne doivent JAMAIS être interceptées ou modifiées.

## 3. Protocole de Repli (Rollback)

En cas de comportement suspect lors des tests :
1.  **Flash Immédiat v3.9.3** : La version actuelle reste stockée et prête à être réinjectée en moins de 2 minutes via OTA.
2.  **Mode "Bypass" logic** : Un switch virtuel sur l'interface web pour désactiver instantanément toute modification de trame (retour au mode fil de fer).
